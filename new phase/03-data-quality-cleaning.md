## Steps

### 3.1 Data Quality Detection
Create `spark_jobs/02_data_quality_checks.py`. For each rule below, write a Spark/Spark SQL check that counts + samples affected rows:
- Missing ticket records (trips with no linked tickets where expected)
- Missing route IDs (nulls / orphan FKs)
- Invalid stop IDs (route_stops referencing non-existent stops)
- Duplicate ticket transactions (same passenger+trip+timestamp)
- Duplicate trips
- Negative passenger counts
- Invalid timestamps (unparseable, out-of-range)
- Impossible arrival times (arrival before scheduled trip start, arrival in the future)
- Departure before arrival
- Vehicle capacity violations (occupancy > 100% without being flagged overcrowded — distinguish real overcrowding from data errors, e.g. occupancy > 300% is an error, 100-150% is real crowding)
- Invalid delay values (negative delay beyond a tiny early-arrival tolerance, or absurd like >600 min)
- Missing vehicle assignments (trip with null vehicle_id)
- Broken stop sequences (gaps or duplicates in route_stops.stop_sequence)
- Invalid route distances (zero/negative)
- Unknown passengers (ticket referencing non-existent passenger_id)
- Missing trip records (schedule/delay/passenger_count referencing non-existent trip_id)

### 3.2 Data Quality Report
Aggregate all the above into `reports/data_quality_report.md` (auto-generated by the script, not hand-written):
- Table: issue type | table | count | % of total rows | severity (low/medium/high)
- Compare your detected counts against `injection_manifest.json` — if your detection rate is low, fix the check.

### 3.3 Cleaning Rules
Create `spark_jobs/03_data_cleaning.py`. For EVERY issue type detected, apply one of: **correct / flag / remove / quarantine**, and write the rule explicitly, e.g.:
```python
# Rule: negative passenger counts -> quarantine (cannot safely infer correct value)
invalid_counts_df = passenger_counts_df.filter(col("boarding_count") < 0)
passenger_counts_df = passenger_counts_df.filter(col("boarding_count") >= 0)
invalid_counts_df.write.mode("overwrite").parquet("processed_data/quarantine/negative_passenger_counts.parquet")
```
Maintain a **cleaning audit log** — write every original record + issue + rule applied + corrected value (or "removed"/"quarantined") + final status to `processed_data/cleaning_audit_log.parquet`. This audit trail is explicitly required by the SRS (Step 5) and will likely be asked about by evaluators.

### 3.4 Cleaning Rule Reference Table (put this in docs, and follow it in code)
| Issue | Rule |
|---|---|
| Missing non-critical field (e.g. optional fare note) | Fill default / flag |
| Duplicate ticket | Keep first occurrence by timestamp, drop rest, log count |
| Negative passenger count | Quarantine row |
| Departure before arrival | Swap if clearly a data-entry swap (both within same trip window), else quarantine |
| Invalid/unparseable timestamp | Quarantine |
| Orphan FK (no matching parent) | Remove + log (cannot analyze an unlinked record) |
| Capacity violation > 300% | Cap/flag as sensor error, quarantine for review |
| Broken stop sequence | Re-sequence where unambiguous, else flag route for manual review |

### 3.5 Output
- Cleaned tables written to `processed_data/clean/<table>.parquet`
- Quarantined records in `processed_data/quarantine/`
- `reports/data_quality_report.md` (before cleaning)
- `reports/cleaning_summary.md` (after cleaning — rows kept/removed/corrected per table)
